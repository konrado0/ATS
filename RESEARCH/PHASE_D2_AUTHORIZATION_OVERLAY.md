following are simultaneously true:

1. the Git commit containing this overlay and the focused D0/D1 v3 baseline is
   the checked-out `HEAD`;
2. the composed v3 `comparison`, `evaluation` and `decision_gate` objects contain
   only the explicit 2023 H1/H2 selection, 2024 H1/H2 development and 2025 H1,
   2025 H2, 2026 H1 locked mappings;

   availability-proof identities and its adversarial rejection tests pass;
4. the D0 v3 validator, D1 v3 validator, independent structural reproduction,
   explicit structural CLI, focused D1 suite, full supported Python suite and
   market-state regressions all pass against that committed tree;
5. the accepted D0/D1 v2 repository evidence and immutable D1 v2 run remain
   byte-identical; and
6. no real label, fit, prediction, score, metric, outcome or model-family result
   was accessed while producing the commit.

The activation commit is the first commit adding this overlay for which all six
conditions pass in a clean post-commit verification. The resulting commit hash
is reported in the implementation handoff; it is not embedded in this file to
avoid a self-referential commit identity.

## Authorized boundary after activation

Authorization covers only a new, explicitly pinned Phase D2 execution of the
frozen four-cell procedure. Phase D2 must generate the ordered 2025 H1, 2025 H2
and 2026 H1 prediction sequence and fingerprint it before attaching outcomes or
computing any metric. Each later refit may use an earlier locked label only when

expected refit session.

comparators, metrics, inference and decision gates cannot change between stages
or after results are viewed.

This overlay does not authorize Phase D3, portfolio translation, deployment,
parameter optimization, alternate models or any contract amendment. A failed
trigger condition leaves Phase D2 unauthorized and requires a versioned repair.
